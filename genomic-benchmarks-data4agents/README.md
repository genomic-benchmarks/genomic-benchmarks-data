# genomic-benchmarks-data4agents

`genomic-benchmarks-data4agents` provides agent-safe access to curated genomic
benchmark datasets. For a comparison of the two packages and the complete
shared API, see the
[project README](https://github.com/genomic-benchmarks/genomic-benchmarks-data).

## Install

```bash
python -m pip install genomic-benchmarks-data4agents
```

Python 3.12 or later is required. Import the package as
`genomic_benchmarks_data4agents`.

## Tutorial

See the
[agent-safe package tutorial](https://github.com/genomic-benchmarks/genomic-benchmarks-data/blob/main/tutorials/genomic-benchmarks-data4agents.ipynb)
for a step-by-step workflow covering discovery, metadata, loading, caching, and
quality control.

## Package-specific boundary

This package exposes `train` and, where supplied by the benchmark, `val`.
`test` and `test_leftout` data and split metadata are excluded.

By default, `load_dataset()` selects the sequence and label columns. Pass
`columns="all"` to include the stable `id`, zero-based `row_index`, and any
other dataset-specific columns.

The cache is in the operating system's standard user cache directory. On
Linux it is `~/.cache/genomic_benchmarks_data4agents`. Download functions
return the exact cached paths.

`add_local_collection(path)` adds a collection from a local folder, as in the
full package, but leaves out its `test` and `test_leftout` splits, and any
dataset that has no other split.

## Package-specific QC

Class QC and reports are available for `train` and `val`. Split QC and reports
are limited to `train`–`val`; datasets without `val` have no split-QC result.
No `test`-related QC information is exposed. Results and self-contained reports
are generated by
[`genomic-benchmarks-qc`](https://github.com/genomic-benchmarks/genomic-benchmarks-qc)
and distributed in the
[`genomic-benchmarks-data4agents` QC Zenodo record](https://zenodo.org/records/23324492),
which contains further provenance and artifact details.
